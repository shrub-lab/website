# 信息架构与内容模型

## 当前线上信息架构

| 路由 | 页面职责 |
| --- | --- |
| `#home` | 实验室入口、核心内容导航与品牌第一印象 |
| `#history` | 按账号和时间组织团队历程 |
| `#works` | 作品检索、筛选与浏览 |
| `#method` | 创作方法、流程和经验沉淀 |
| `#assets` | 脚本、镜头、Prompt、工程、模型、贴图和音频等资产索引 |
| `#detail` | 单个账号介绍、数据、作品与时间线 |
| `#about` | 实验室定位、正在构建的能力、关注点与联系入口 |

## 当前内容规模

- 账号：名做茶友会、国粹儿、丝路、灌木新媒体实验室。
- 作品库：20 条。
- 作品分类：美食、非遗技艺、才艺、国风美学、中式建筑、科技 AI。
- 资产库：9 组分类。
- 名做茶友会详情：账号数据与 10 条内容展示。

## 建议的新项目数据边界

新项目不要把 JSON 和图片继续嵌入 HTML。建议按以下边界组织：

- `accounts`：账号元数据、运营阶段、外链、封面。
- `works`：作品标题、日期、账号、分类、标签、描述、封面、平台数据。
- `timelines`：账号历程节点、镜头配置、对应场景和交互。
- `assets`：内部资产库分组、条目、文件位置和可见性。
- `methods`：方法论章节与案例关联。
- `site`：导航、联系信息、SEO、版本与部署配置。

已导出的 `data/*.json` 是迁移起点，不代表最终字段设计。迁移时需补充稳定 ID，避免继续使用标题作为关联键。

## 数据可信度提醒

线上内容混合了正式数据、占位数据和演示内容。尤其需要再次确认：

- 账号粉丝量与点赞量是否仍为当前数据。
- 作品标题、发布日期与真实平台链接。
- 资产库数量是实际库存还是展示数字。
- 联系邮箱 `hello@example.com` 是占位符，不能用于正式上线。
- 名做茶友会最初需求为 8 条 2023 年作品，但线上详情当前使用 10 条展示内容，重启时需统一口径。
